#The Pivot interface is essentially a visual query builder. It constructs SPL behind the scenes.

Pivot editor works with Datasets.
Datasets are created by data managers in organization and they are the rule and constraints that govern data.
Analysts can then use Pivot editors to build visualizations based on those Datasets.

Data Models > MyDataModel > Pivot (select dataset to work)
Revenue by Product summary:

| pivot myDataModel AllSales
    count(AllSales) AS "Count of AllSales"
    sum(Price) AS "Sum of Price"
    SPLITROW Product AS Product
    SPLITCOL Payment_Type

SPLITROW Product — groups transactions by product.
SPLITCOL Payment_Type — creates separate column groups for each payment method.


Conclusion:
Indexes store and make data searchable. SPL searches and analyzes it. Data Models organize it into reusable business structures. 
Pivot lets people explore those structures without writing SPL.

Simple queries could be:
index=salesreport
| stats sum(Price) as Revenue by Product
| sort - Revenue

or

index=salesreport Payment_Type="Visa"
| stats sum(Price) as Revenue by Country

But when we need Organizing data for reuse: Data Model
for a retail company.

Different teams want to analyze the same sales data:
- Finance wants revenue by product.
- Sales wants transactions by payment method.
- Management wants high-value transactions.
- Regional managers want sales by country.
Without a Data Model, each person might write their own SPL query, remember the index name, 
remember field names, and apply the right filters.

So with data model:someone can use a predefined dataset rather than remembering all the underlying index constraints.
Ex:
| datamodel myDataModel Visa_Transactions flat
| stats count by Country

Data Model provides a common structure that Pivot, dashboards, and other Splunk capabilities can use.

#Acceleration
Without acceleration, Splunk calculates your results by searching the underlying events. 
With acceleration, Splunk maintains precomputed summaries that can be reused for supported searches.

Say we run:
index=salesreport
| stats sum(Price) as Revenue by Product

Every time this search runs, Splunk searches the matching events and calculates the revenue for each product.

With Data Model Acceleration
We already created myDataModel, with AllSales as its root dataset.
we can enable acceleration for this Data Model.
Splunk then builds and maintains summaries for eligible fields and calculations over the selected time range.

Settings> data models
Edit> edit acceleration > but first edit permissions (all Apps: read and write)
Then we can edit acceleration
Check Accelerate.
Set Summary Range to All Time.

(in Advanced settings:
Backfill range: All time --Build summaries for all existing indexed data within the model's constraints.
Max summarization searchtime:1 hour --Maximum time allowed for an individual summarization search.
Custom max time: 3600 --1hour
Maximum concurrent summarization searches: 3 --	Allow up to three summarization searches concurrently.
Poll buckets for data to summarize: not checked --Splunk uses its normal scheduling mechanism rather than polling buckets.
Summarization period: */5 * * * * --Schedule summarization every five minutes.
Automatic rebuilds: selected --Allow Splunk to rebuild summaries when necessary.
)

Splunk starts building the acceleration summary. Initially, its status may show Building; wait until it reports Complete.
Return to Settings → Data Models, expand myDataModel, and look for:
Metric		What it tells you
Status		Whether summary building is complete
Access Count	How often the summary has been used
Size on Disk	Storage consumed
Summary Range	How far back data is summarized
Updated		When the summary was last updated

After summary is built:
| tstats sum(AllSales.Price) as Revenue
  from datamodel=myDataModel
  by AllSales.Product

compare with non accelerated version:
index=salesreport
| stats sum(Price) as Revenue by Product

tstats is particularly useful because it can retrieve statistical results from accelerated Data Models without reading all the underlying raw events.
