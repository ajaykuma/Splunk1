##Commands

#Eval command
------------------
eval evaluates an expression and stores its result in a field.
- Can create a new field.
- Can modify an existing field.
- Supports mathematical, logical, comparison and string operations.
- Supports many built-in functions.

index="xxx"
| eval new_field = expression
| table field1 field2 new_field
eval is a transforming field-calculation command, but it does not aggregate events. It normally preserves the number of events.

#Concatenating fields using eval
--'+' operators
index="_internal"
| eval uriInfo = uri_query + uri + uri_path
| table uri_query uri uri_path uriInfo

--For predictable string concatenation, use . instead.
--The . operator performs string concatenation. It is the preferred operator when combining text fields.

For example:
index="_internal"
| eval uriInfo = uri_query . uri . uri_path
| table uri_query uri uri_path uriInfo

#Concatenating fields with descriptive text
--This creates a combined field containing information from three different fields.
index="_internal"
| eval uriInfo = "URI_QUERY: " . uri_query .
                 " URI: " . uri .
                 " URI_PATH: " . uri_path
| stats count by uriInfo
| table uriInfo count


#concatenating
index="_internal" 
| eval uriInfo = "URI_QUERY: " + uri_query + " URI: " + uri + " URI_PATH: "+ uri_path 
|  stats count by uriInfo 
|  table uriInfo count 

#modifying an existing field
[however not for an internal index]
index="_internal" 
| eval 'useragent' = 'useragent' + 'user'
|  table user,useragent

Here:- useragent is the existing field.
- user is another existing field.
- The result overwrites useragent.
Note: This only changes the field in the search results. It does not modify the original indexed event.

##Conditional evaluation using case()
--case() evaluates multiple conditions and returns the value associated with the first matching condition.
Syntax:
| eval new_field = case(
    condition1, value1,
    condition2, value2,
    condition3, value3
)

#eval chains & using case
index="_internal"
| eval splunk_server="HP",
       description=case(
           status == 200, "GOOD",
           status == 404, "Not found",
           status == 201, "Created",
           status == 204, "No Content",
           status == 400, "Bad Request"
       )
| table splunk_server status description

Note*
Conditions are evaluated from left to right.
The first matching condition wins.
If none matches, case() returns NULL.
Add a default condition 1=1 at the end if you want a fallback.

index="_internal"
| eval description=case(
    status == 200, "GOOD",
    status == 404, "Not found",
    status == 201, "Created",
    1=1, "Other status"
)
| table status description

##Conditional evaluation using validate()
--validate() is different from case().
It returns the value associated with the first condition that evaluates to FALSE. If all conditions are TRUE, it returns NULL.
#using validate
Syntax:
| eval new_field=validate(condition1, value1, condition2, value2)


index="_internal"
| eval description=validate(
    status == 200, "not 200",
    status == 404, "not 404"
)
| table splunk_server status description

Function	What it checks
case()	Returns the value for the first TRUE condition
validate()	Returns the value for the first FALSE condition

#Example with a default condition
index="_internal" status=201
| eval description=validate(
    status == 200, "Not 200",
    status == 404, "Not 404",
    1=1, "Status"
)
| table status description

--For status 201, the result is "Not 200" because the first condition is already false. The 1=1 condition is never reached.
Remember: validate() is useful for validation logic, but case() is generally more intuitive for assigning descriptive categories.

##Conditional evaluation using if()
if() evaluates a condition and returns one of two values.

#using if
Syntax: | eval new_field=if(condition, true_value, false_value)

index="_internal" status=201
| eval description=if(status == 200, "Its good", "Its not good")
| table splunk_server status description

or

Nested If:
index="_internal" status=201
| eval description=if(
    status == 200, "Its 200",
    if(status == 404, "Its 404", "Neither 200 nor 404")
)
| table splunk_server status description

or
--Using in() inside if()

index="_internal" component="*"
| eval impComponents=if(
    component IN ("Metrics", "PeriodicHealthReporter", "LMStackManager"),
    "condmet",
    "condnotmet"
)
| table impComponents component
| stats count by impComponents component

##Filtering records using where
where filters events based on an expression.
#using where
index="_internal" component="*"
| where component IN (
    "Metrics",
    "PeriodicHealthReporter",
    "LMStackManager"
)
| table component
| stats count by component

--Extract EventCode from raw XML
--rex extracts the numeric value inside <EventID> and creates a field called EventCode.
--table displays the timestamp and extracted event code.

index=botsv1 sourcetype="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational"
| rex "<EventID>(?<EventCode>\d+)</EventID>"
| table _time EventCode

--Use eval to classify events
--eval creates a new field called Event_Type.
--If EventCode is 1, it assigns Process Creation.Otherwise, it assigns Other Event.
index=botsv1 sourcetype="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational"
| rex "<EventID>(?<EventCode>\d+)</EventID>"
| eval Event_Type=if(EventCode=1,"Process Creation","Other Event")
| table _time EventCode Event_Type

--Use stats to count event types
--stats count counts the events.
--by Event_Type groups the counts by the classification created using eval

index=botsv1 sourcetype="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational"
| rex "<EventID>(?<EventCode>\d+)</EventID>"
| eval Event_Type=if(EventCode=1,"Process Creation","Other Event")
| stats count by Event_Type

##Combining where, eval, and stats
--rex extracts the event ID.
--where EventCode=7 retains only Event ID 7 events.
--eval assigns the label Image Loaded.
--stats counts the matching events.

index=botsv1 sourcetype="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational"
| rex "<EventID>(?<EventCode>\d+)</EventID>"
| where EventCode=7
| eval Event_Type="Image Loaded"
| stats count by Event_Type

--Classify multiple event IDs using case
--case() checks conditions from top to bottom and returns the value for the first matching condition. 1=1 acts as the default condition.
index=botsv1 sourcetype="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational"
| rex "<EventID>(?<EventCode>\d+)</EventID>"
| eval Event_Type=case(
    EventCode=1,"Process Creation",
    EventCode=5,"Process Termination",
    EventCode=7,"Image Loaded",
    1=1,"Other Event"
)
| stats count by Event_Type

--count only selected event types
index=botsv1 sourcetype="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational"
| rex "<EventID>(?<EventCode>\d+)</EventID>"
| where EventCode=1 OR EventCode=5 OR EventCode=7
| eval Event_Type=case(
    EventCode=1,"Process Creation",
    EventCode=5,"Process Termination",
    EventCode=7,"Image Loaded"
)
| stats count by Event_Type

--Count process creation and termination events by date
index=botsv1 sourcetype="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational"
| rex "<EventID>(?<EventCode>\d+)</EventID>"
| where EventCode IN (1,5)
| eval Event_Type=case(
    EventCode=1,"Process Creation",
    EventCode=5,"Process Termination"
)
| eval Date=strftime(_time,"%Y-%m-%d")
| stats count by Date Event_Type
| sort Date

--Use chart to display the counts
index=botsv1 sourcetype="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational"
| rex "<EventID>(?<EventCode>\d+)</EventID>"
| where EventCode IN (1,5)
| eval Event_Type=case(
    EventCode=1,"Process Creation",
    EventCode=5,"Process Termination"
)
| eval Date=strftime(_time,"%Y-%m-%d")
| chart count over Date by Event_Type

--Use timechart for a line chart
--timechart automatically uses _time for its time buckets. You don't need to create a separate date field or group by that date field.
index=botsv1 sourcetype="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational"
| rex "<EventID>(?<EventCode>\d+)</EventID>"
| where EventCode IN (1,5)
| eval Event_Type=case(
    EventCode=1,"Process Creation",
    EventCode=5,"Process Termination"
)
| timechart span=7d count by Event_Type

--Using like and if
like(Event_Type,"%Process%") checks whether the text contains Process.
% is a wildcard representing zero or more characters.
if() returns ProcessRelated when the condition is true; otherwise, it returns NotNeeded.

index=botsv1 sourcetype="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational"
| rex "<EventID>(?<EventCode>\d+)</EventID>"
| eval Event_Type=case(
    EventCode=1,"Process Creation",
    EventCode=5,"Process Termination",
    EventCode=7,"Image Loaded",
    1=1,"Other Event"
)
| eval cat_of_interest=if(like(Event_Type,"%Process%"),"ProcessRelated","NotNeeded")
| table _time EventCode Event_Type cat_of_interest

--Using coalesce()
In a multi-vendor environment, different systems may use different field names for the same information.

For example:
- src_ip
- sourceip
- source_ip
- sip
- ip
We can normalize these into a common field:

index=botsv1
| eval new_field=coalesce(dest,dest_ip)
| table dest dest_ip new_field
| stats count by new_field
| sort - count

| makeresults

#dedup command
dedup is used to remove duplicate events based on one or more fields.
The dedup command normally removes events that have null values in the fields specified for deduplication.

#Deduplicate source IP addresses
index=botsv1 sourcetype=stream:dns
| dedup src_ip
| table _time src_ip dest_ip dest_port transport

--Here, src_ip has actual values, so dedup should work.
--It will retain one event per unique source IP.

#Deduplicate destination IP addresses
index=botsv1 sourcetype=stream:dns
| dedup dest_ip
| table _time src_ip dest_ip

#Find events where the DNS query field is populated
index=botsv1 sourcetype=stream:dns query=*
| table _time src_ip dest_ip query query_type

--it will tell us whether the DNS domain names are actually available in your indexed events
--returns nothing because the query field appears to be empty in the DNS events.

#Splunk often chooses a column chart as the default visualization for timechart results (we can change to line chart)
#timechart — DNS events per hour
--Splunk groups the DNS events into one-hour intervals and counts the events in each interval.
index=botsv1 sourcetype=stream:dns
| timechart span=1h count

#DNS events per hour, grouped by source IP
--produces separate time-series lines for each source IP.
--This helps identify which systems generated DNS traffic and when.
index=botsv1 sourcetype=stream:dns
| timechart span=1h count by src_ip

#Count unique source IPs per hour
index=botsv1 sourcetype=stream:dns
| timechart span=1h dc(src_ip) AS Unique_Source_IPs

dc() means distinct count

Visualization	Best suited for
Column chart	Comparing counts between time intervals
Line chart	Observing trends, spikes, and patterns over time
Area chart	Showing volume and trends with filled areas
